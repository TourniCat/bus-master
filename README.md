# Bus Master — Topology Puzzle Prototype

Bus Master는 OpenStreetMap 원본 지도를 그대로 플레이시키는 대신, **실제 도시의 도로망/POI/건물 분포를 추상적인 버스 퍼즐 그래프로 변환하는 방식**을 테스트합니다.

핵심 질문:

> **실제 도시에서 추출한 topology가, raw 지도를 숨겼을 때도 재미있는 노선 퍼즐이 되는가?**

현재 테스트 지역은 강남역 주변입니다.

## Windows 빠른 실행

```powershell
git pull
.\run_prototype.bat
```

처음 실행할 때는 인터넷 연결이 필요합니다. OSM 데이터를 Overpass API에서 받아 로컬 캐시에 저장합니다.

## v0.4.0 핵심 변화

- raw OSM 도로/건물 지도 렌더링 제거
- OSM은 내부 데이터로만 사용
- 실제 도로 그래프에서 약 10개의 `Puzzle Stop` 추출
- 실제 POI/건물 밀도로 Home / Hub / Shops / Work / School 등의 타입을 우선 생성
- 나머지 노드는 실제 도로망에서 서로 떨어진 후보를 선택
- 노드 배치는 실제 위치 관계를 바탕으로 하되 읽기 쉽게 약간 정리
- 노드 사이 연결선은 실제 도로망의 접근 거리/연결성을 바탕으로 생성
- 플레이어는 정류장을 직접 설치하지 않음
- 처음에는 3개 Stop만 활성화
- Route 1으로 노드를 클릭해 연결한 뒤 `START`
- 수송량이 늘면 새 Stop이 순차적으로 공개
- Route 2 / Route 3도 진행 중 해금
- 각 노드에 목적지 수요가 쌓임
- 노선별 처리량보다 수요가 많으면 대기열이 증가
- 한 노드의 대기 수요가 한계를 넘으면 Game Over

즉 이번 버전에서 OSM은 **화면 디자인이 아니라 퍼즐 seed** 역할을 합니다.

## 첫 플레이

1. 화면에 보이는 3개 활성 Stop을 확인합니다.
2. 기본 선택된 `R1` 상태에서 Stop을 원하는 순서대로 클릭합니다.
3. 최소 2개를 연결하면 `START`를 누를 수 있습니다.
4. 목적지 문자 수요가 각 Stop 아래 쌓이는 것을 봅니다.
5. 새 Stop이 나타나면 기존 노선을 늘리거나 새 노선을 사용합니다.
6. 과밀이 발생하기 전에 노선을 다시 설계합니다.

노선의 마지막 Stop을 다시 클릭하면 마지막 추가를 취소합니다.

## 조작

- 노드 클릭: 현재 노선에 추가
- `R1 / R2 / R3`: 편집할 노선 선택
- `START / PAUSE / RESUME`: 시뮬레이션 제어
- `Reset Run`: 같은 OSM 퍼즐을 처음부터 다시 시작
- `Reload OSM`: 캐시 삭제 후 OSM 재다운로드
- 마우스 휠: 확대/축소
- 마우스 가운데 버튼 드래그: 화면 이동
- `1 / 2 / 3`: 노선 선택
- `Space`: 시작/일시정지
- `R`: 리셋
- `0`: 시점 리셋

## 이번 테스트에서 볼 것

이번에는 실제 강남처럼 보이는지가 중요하지 않습니다.

- 처음 화면이 즉시 읽히는가?
- 노드를 어떤 순서로 묶을지 고민하게 되는가?
- 새 노드가 추가되면서 기존 노선을 다시 고칠 이유가 생기는가?
- 제한된 노선 슬롯이 실제 선택을 만드는가?
- 대기 수요가 쌓일 때 대응하고 싶은 압박이 생기는가?
- 실패 후 다른 노선 구조로 다시 해보고 싶은가?

이 버전도 재미가 없다면, OSM 표현 방식보다 **버스 노선 퍼즐 자체의 핵심 메커니즘**을 다시 검토합니다.

## 오류 로그

`run_prototype.bat` 실행 중 문제가 생기면:

```text
copy_latest_log.bat
```

을 실행한 뒤 이 채팅에 붙여넣으면 됩니다.

## 데이터 메모

공용 Overpass API는 프로토타입 개발용입니다. 정식 제품은 공용 서버를 게임 백엔드처럼 사용하지 않습니다.

게임 화면에는 OpenStreetMap attribution을 유지합니다.
