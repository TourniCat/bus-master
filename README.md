# Flow Control — Procedural Puzzle Prototype

Flow Control은 **이미 존재하는 네트워크 위에서 여러 흐름이 동시에 목적지로 이동하고, 플레이어가 제한된 규칙 변경으로 병목을 줄이는 실시간 퍼즐**을 테스트하는 프로젝트입니다.

현재 단계에서는 OSM이나 버스 테마를 사용하지 않습니다. 먼저 절차 생성 그래프만으로 반복 플레이가 재미있는지 검증합니다.

## v0.4.0 — Rush Waves

이번 버전의 목표는 `한 번 최적화한 뒤 가만히 보는 게임`에서 벗어나는 것입니다.

### Speed

오른쪽 패널에 `x1 / x2 / x3` 배속 버튼을 추가했습니다.

키보드 `1 / 2 / 3`으로도 변경할 수 있습니다. 배속은 흐름 이동, 생성, Rush 타이머, 과부하 판정 등 시뮬레이션 전체에 적용됩니다.

### Rush Waves

약 20~30초 간격으로 특정 색상의 수요가 짧게 급증합니다.

- Rush 시작 5초 전 색상과 카운트다운 표시
- 해당 색상의 IN에 펄스 표시
- Rush 동안 해당 색상이 생성 시도의 대부분을 차지
- Rush가 끝나면 다음 Rush는 다른 색이 우선 선택됨

목표는 플레이어가 한 번 만든 도로 설정을 그대로 방치하지 않고, `지금 어느 흐름이 몰리는가`에 따라 일방통행/폐쇄/우회 판단을 다시 하게 만드는 것입니다.

### WIDEN 시각화

WIDEN한 도로는 이제 일반 도로와 확실히 구분됩니다.

- 도로 외곽이 더 굵고 진하게 표시
- 도로 중앙에 `+1`, `+2` 형태의 Capacity 배지 표시

### 기존 핵심 규칙

- 3색 흐름이 각 IN에서 같은 색 OUT으로 이동
- 흐름은 현재 혼잡과 대기열을 보고 동적으로 우회
- 최근 방문 노드 재방문/U턴에는 큰 비용을 줘 왕복 진동 억제
- 도로 클릭: `↔ → ← ×`
- 일방통행은 해당 도로 Capacity +1
- 일정 점수마다 목적지가 회전하고 인프라 업그레이드 선택
- `WIDEN / BYPASS / +CTRL`
- BYPASS는 한 맵에서 최대 1개
- 교차점 대기열이 오래 과밀하면 Game Over
- 280 Score에 도달하면 Map Clear

## 실행

```powershell
git pull
.\run_prototype.bat
```

Godot 4.7.x에서 `project.godot`을 직접 열어도 됩니다.

## 조작

- `START / PAUSE / RESUME`
- `x1 / x2 / x3`: 배속
- `RESET`: 같은 맵 처음부터
- `NEW MAP`: 새 절차 생성 맵
- `Space`: 시작/일시정지
- `1 / 2 / 3`: 배속
- `R`: Reset
- `N`: New Map

## 이번 테스트에서 볼 것

이번 버전에서 중요한 건 난이도보다 **동적인 재미**입니다.

- x2/x3가 답답한 대기 시간을 줄이는가?
- Rush 예고를 보면 실제로 도로 설정을 손대고 싶어지는가?
- Rush 색상이 바뀔 때 병목 위치도 바뀌는가?
- WIDEN한 도로가 즉시 구분되는가?
- 한 번 최적화한 뒤 방치하는 플레이가 여전히 가능한가?
- Rush가 불공정한 랜덤 패배가 아니라 대응 가능한 문제로 느껴지는가?

이 단계에서도 여전히 정적이라면 수치 조정보다 **플레이어가 직접 조작하는 대상 자체를 더 크게 바꾸는 방향**을 검토합니다.

## OSM

OSM은 현재 코어에서 제외했습니다. 절차 생성 버전이 충분히 재미있어진 뒤 `Real World`용 추가 맵 소스로만 검토합니다.
