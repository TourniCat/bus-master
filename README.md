# Flow Control — Procedural Puzzle Prototype

Flow Control은 **이미 존재하는 네트워크 위에서 여러 흐름이 동시에 목적지로 이동하고, 플레이어가 제한된 규칙 변경으로 병목을 줄이는 실시간 퍼즐**을 테스트하는 프로젝트입니다.

현재 단계에서는 OpenStreetMap과 버스 테마를 사용하지 않습니다. 먼저 절차 생성 그래프만으로 반복 플레이가 재미있는지 검증합니다.

## 핵심 아이디어

Mini Metro가 `네트워크를 만든 뒤 흐름을 처리하는 게임`이라면, Flow Control은 반대로:

> **네트워크는 이미 존재한다 → 흐름이 꼬인다 → 플레이어가 규칙을 바꿔 병목을 관리한다.**

## v0.3.0 — Stable Pressure

이번 버전은 두 가지 문제를 해결합니다.

1. 흐름이 혼잡도 변화에 과민하게 반응해 같은 두 교차점을 왕복하는 현상
2. BYPASS 몇 개를 만든 뒤 플레이어가 아무것도 하지 않아도 무한히 안정화되는 현상

### Anti-loop routing

흐름은 여전히 각 교차점에서 혼잡도를 보고 동적으로 경로를 다시 계산하지만, 최근 지나온 교차점을 기억합니다.

- 방금 지나온 교차점으로 즉시 되돌아가는 경로에는 매우 큰 패널티
- 최근 방문한 다른 교차점에도 반복 방문 패널티
- 정말 다른 길이 없을 때는 되돌아갈 수 있으므로 막다른 길에서 영구 정지하지 않음

즉 동적 우회는 유지하면서 `A → B → A → B` 식의 진동을 억제합니다.

### Traffic stages

한 판은 이제 무한 생존형이 아니라 **여러 교통 패턴을 연속해서 해결하는 짧은 맵 클리어 구조**를 테스트합니다.

임시 진행 기준:

- 30 Score
- 70 Score
- 120 Score
- 180 Score
- 250 Score
- 330 Score에서 Map Clear

각 중간 점수에 도달하면 게임이 잠시 멈추고 인프라 업그레이드를 하나 선택합니다. 업그레이드를 적용하면 **세 색상의 목적지가 회전**하고 다음 교통 패턴이 시작됩니다.

따라서 한 번 만든 정답이 판 끝까지 그대로 유지되지 않습니다.

### Infrastructure

선택지:

- `WIDEN` — 도로 하나 Capacity +1
- `BYPASS` — 가까운 두 교차점을 새 연결도로로 연결
- `+CTRL` — 동시에 사용할 수 있는 Control +1

BYPASS는 너무 강했던 이전 버전 때문에 다음 제한을 둡니다.

- 한 맵에서 최대 1회
- 최대 연결 거리 제한
- 기본 Capacity 1

### Road controls

도로 클릭 시:

```text
↔  양방향
→  A에서 B 방향만 허용
←  B에서 A 방향만 허용
×  폐쇄
```

순서로 바뀝니다.

일방통행으로 바꾸면 해당 도로의 동시 처리 Capacity가 +1 됩니다. 즉 방향 제어는 단순히 경로를 막는 기능이 아니라 실제 처리량을 높이는 선택이기도 합니다.

## 기본 규칙

- 매 판 새로운 절차 생성 네트워크
- 3개의 색상 흐름
- 각 색은 왼쪽 `IN`에서 출발해 같은 색의 오른쪽 `OUT`으로 이동
- 흐름은 거리, 도로 점유율, 꽉 찬 도로, 다음 교차점 대기열을 고려해 경로 선택
- 도로에는 동시 통과 Capacity가 존재
- 교차점 대기열이 오래 과밀하면 Game Over
- 점수가 오를수록 새 Traffic Stage가 열리고 목적지 조합이 바뀜
- 330 Score에 도달하면 해당 맵 Clear

## 실행

PowerShell에서 저장소 루트로 이동한 뒤:

```powershell
git pull
.\run_prototype.bat
```

또는 Godot 4.7.x에서 `project.godot`을 직접 열어 실행할 수 있습니다.

## 버튼 / 키보드

- `START / PAUSE / RESUME`: 시뮬레이션 제어
- `RESET`: 같은 맵에서 처음부터 다시 시작. 도로 규칙과 인프라도 초기화
- `NEW MAP`: 새로운 절차 생성 맵
- `Space`: 시작/일시정지
- `R`: Reset
- `N`: New Map

## 이번 테스트에서 볼 것

- 흐름이 같은 두 교차점을 왕복하는 현상이 사실상 사라졌는가?
- 혼잡한 도로를 피해 우회하는 움직임이 자연스러운가?
- 일방통행의 +Capacity가 실제로 유용한 선택처럼 느껴지는가?
- BYPASS 하나가 강력하지만 자동 승리 버튼은 아닌가?
- Traffic Stage가 바뀔 때 기존 정답을 다시 손봐야 하는가?
- 330점 Map Clear까지 플레이어 개입이 계속 필요한가?
- 실패했을 때 `내가 다르게 했으면 해결 가능했다`는 느낌이 드는가?

## OSM 관련

OpenStreetMap은 현재 프로토타입에서 제거했습니다.

절차 생성 버전 자체가 충분히 재미있다는 것이 확인된 뒤에만 선택적으로 검토합니다.

가능한 장기 구조:

- Procedural — 메인 모드
- Daily Seed — 동일 맵 경쟁
- Real World — OSM에서 재미있는 그래프를 추출하는 별도 모드
