# Bus Master — Prototype

Bus Master의 첫 번째 **게임성 검증용 프로토타입**입니다.

이 단계에서는 실제 지도, OSM, 3D 그래픽, Kenney 에셋, 경제, 방치형 성장 요소를 일부러 제외합니다. 검증 질문은 하나입니다.

> **제한된 버스와 노선을 배치하고, 시간대별로 쌓이는 승객을 보며 노선을 계속 손보는 행동 자체가 재미있는가?**

## Windows 빠른 실행

최신 버전을 받은 뒤 저장소 루트의 아래 파일을 더블클릭합니다.

```text
run_prototype.bat
```

런처가 Godot을 찾아 프로토타입을 실행하고, 콘솔 출력과 엔진/스크립트 오류를 자동으로 기록합니다.

### Godot을 못 찾는 경우

런처는 다음 순서로 Godot 실행 파일을 찾습니다.

1. `GODOT_PATH` 환경 변수
2. 프로젝트 폴더 또는 `tools/` 안의 Godot 실행 파일
3. 사용자 `Downloads` 폴더의 Godot console 실행 파일
4. Windows `PATH`
5. 일반적인 Godot/Steam 설치 위치

그래도 못 찾으면 Godot console 실행 파일을 프로젝트 폴더에 넣는 것이 가장 간단합니다.

또는 Windows 터미널에서 한 번만 설정할 수 있습니다.

```bat
setx GODOT_PATH "C:\Path\To\Godot_v4.x-stable_win64_console.exe"
```

새 터미널 또는 새로 실행한 BAT부터 적용됩니다.

## 오류 로그 보내는 방법

`run_prototype.bat`으로 실행하면 자동으로 다음 로그가 생깁니다.

```text
logs/prototype_latest.log
```

매 실행마다 이전 기록도 다음 형태로 보관됩니다.

```text
logs/prototype_YYYYMMDD_HHMMSS.log
```

오류가 났다면 저장소 루트의:

```text
copy_latest_log.bat
```

을 더블클릭합니다. 최신 로그 전체가 Windows 클립보드에 복사됩니다.

그 다음 이 채팅에 **Ctrl+V**로 그대로 붙여넣으면 됩니다.

로그 파일은 `.gitignore` 처리되어 GitHub에는 올라가지 않습니다.

## Godot 에디터에서 직접 실행

BAT을 사용하지 않으려면:

1. Godot 4.x에서 이 저장소 폴더를 Import 합니다.
2. `project.godot`을 엽니다.
3. 프로젝트를 실행합니다.

별도 에셋이나 플러그인은 필요 없습니다.

## 조작

- 화면 하단 `Route 1 / 2 / 3`: 편집할 노선 선택
- 지도 위 정류장 클릭: 선택한 노선에 순서대로 추가
- 선택한 노선의 마지막 정류장을 다시 클릭: 마지막 정류장 취소
- `+ Bus / - Bus`: 선택한 노선의 차량 증감
- `Start / Pause`: 시뮬레이션 시작/일시정지
- `Reset`: 초기화

키보드도 지원합니다.

- `1 / 2 / 3`: 노선 선택
- `+ / -`: 버스 증감
- `Space`: 시작/일시정지
- `R`: 초기화

## 현재 규칙

- 최대 노선: 3개
- 전체 버스: 최대 6대
- 노선당 최대 정류장: 6곳
- 버스 정원: 12명
- 버스는 노선의 양 끝을 왕복합니다.
- 승객은 목적지와 출발지가 모두 같은 노선에 포함되어 있어야 탑승합니다.
- 환승은 아직 없습니다.
- 하루는 압축되어 빠르게 흐릅니다.
- 출근 시간에는 주거지 → 학교/역/업무지구 수요가 많습니다.
- 낮에는 쇼핑/공원/병원 수요가 늘어납니다.
- 퇴근 시간에는 업무지구/학교/역 → 주거지 수요가 늘어납니다.
- 정류장의 붉은 원과 숫자가 커질수록 대기 승객이 많다는 뜻입니다.

## 첫 플레이 권장 방식

처음부터 모든 곳을 연결하려 하지 말고 다음처럼 테스트합니다.

1. Route 1로 `Homes W → Station → Offices`를 연결하고 버스 2대를 넣습니다.
2. Route 2와 Route 3은 비워 둔 채 시작합니다.
3. 어떤 정류장이 터지는지 1~2분 관찰합니다.
4. 운행 중에도 노선을 추가하거나 버스를 재배치합니다.
5. Rating과 Waiting 수치가 실제로 개선되는지 확인합니다.
6. Reset 후 완전히 다른 방식으로 다시 설계합니다.

## 개발 착수 여부 판단 기준

한두 번 플레이한 뒤 아래 질문에 답합니다.

- 대기열이 쌓이는 걸 보고 **노선을 고치고 싶다는 생각**이 자연스럽게 들었나?
- 노선을 수정한 뒤 문제가 풀리는 모습이 만족스러웠나?
- 제한된 6대를 어디에 배치할지 고민하게 됐나?
- 시간대가 바뀌자 기존의 좋은 노선이 나빠지는 것이 재미있었나?
- Reset을 눌러 다른 구조를 시험해보고 싶었나?
- 이 시스템을 실제 우리 동네 지도에서 해보고 싶다는 생각이 들었나?

**4개 이상 YES:** 실제 지도 기반 Vertical Slice로 진행할 가치가 높음.

**2~3개 YES:** 핵심 규칙을 수정한 뒤 한 번 더 프로토타이핑.

**0~1개 YES:** OSM/3D 작업에 들어가기 전에 게임 방향 자체를 재검토.
