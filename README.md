# Bus Master — OSM Map Prototype

현재 Bus Master는 **실제 OpenStreetMap 도로 위에서 버스 정류장을 놓고 노선을 연결하는 감각**을 검증하는 단계입니다.

핵심 질문은 하나입니다.

> **실제 도시의 도로 구조 자체가 버스 노선 퍼즐판으로 재미있는가?**

현재 실행되는 프로토타입은 강남역 주변 약 2 km급 구역을 기본 테스트 맵으로 사용합니다.

## Windows 빠른 실행

최신 버전을 받은 뒤 저장소 루트의 아래 파일을 더블클릭합니다.

```text
run_prototype.bat
```

처음 실행할 때는 인터넷 연결이 필요합니다. 프로토타입이 OpenStreetMap 데이터를 Overpass API에서 받아 로컬 캐시에 저장합니다.

두 번째 실행부터는 캐시된 지도를 사용하므로 같은 데이터를 다시 다운로드하지 않습니다.

## 현재 구현된 OSM 요소

- 실제 도로망
- 실제 건물 footprint
- 공원
- 수면 영역
- 학교/병원/상점/관광/교통 관련 일부 POI
- 실제 도로 노드를 이용한 경로 탐색
- 도로 위 정류장 설치
- 최대 3개 버스 노선
- 정류장을 순서대로 선택하면 실제 도로를 따라 노선 표시

현재 단계에서는 **버스 운행, 승객 수요, 게임오버는 아직 연결하지 않았습니다.** 먼저 실제 도로 위에 노선을 그리는 경험을 확인합니다.

## 조작

### 마우스

1. `Place Stop` 선택
2. 지도 위 도로를 클릭해 정류장 설치
3. `R1`, `R2`, `R3` 중 하나 선택
4. 설치한 정류장을 원하는 순서대로 클릭
5. 노선이 실제 도로를 따라 생성되는지 확인

선택한 노선의 **마지막 정류장을 다시 클릭하면 마지막 연결을 취소**합니다.

### 키보드

- `S`: 정류장 설치 모드
- `1 / 2 / 3`: 노선 1/2/3 편집
- `R`: 정류장과 노선 초기화

## 지도 버튼

- `Place Stop`: 정류장 설치 모드
- `Clear Stops / Routes`: 정류장과 노선만 초기화
- `Reload OSM`: 로컬 OSM 캐시를 지우고 서버에서 다시 다운로드

공용 Overpass API는 프로토타입 개발용입니다. 정식 제품은 공용 서버를 게임 백엔드처럼 사용하는 구조로 출시하지 않습니다.

## 오류 로그 보내는 방법

`run_prototype.bat`으로 실행하면 다음 파일에 최신 로그가 저장됩니다.

```text
logs/prototype_latest.log
```

오류가 나면 저장소 루트의:

```text
copy_latest_log.bat
```

을 더블클릭한 뒤 이 채팅에 `Ctrl+V`로 붙여넣으면 됩니다.

로그 파일은 Git에서 무시됩니다.

## Godot을 못 찾는 경우

런처는 `GODOT_PATH`, 프로젝트 주변, Downloads, PATH 및 일반 설치 위치를 순서대로 탐색합니다.

필요하면 Windows 터미널에서 한 번만 설정합니다.

```bat
setx GODOT_PATH "C:\Path\To\Godot_v4.x-stable_win64_console.exe"
```

## 이번 플레이에서 확인할 것

아직 게임의 재미를 평가할 단계보다는 **맵 표현과 노선 감각**을 봅니다.

- 강남의 실제 도로망처럼 보이는가?
- 지도 정보가 너무 복잡하거나 지저분하지 않은가?
- 정류장을 원하는 곳에 놓기 쉬운가?
- 두 정류장을 연결했을 때 실제 길을 따라가는 노선이 자연스러운가?
- 실제 도로의 우회/교차로/큰길 구조가 퍼즐 제약처럼 느껴질 가능성이 보이는가?
- 2D 지도 자체가 게임 화면으로 충분히 보기 좋은가?

이 단계가 괜찮으면 다음 순서로 진행합니다.

1. 버스를 노선 위에서 실제로 이동
2. 정류장별 승객 수요 생성
3. 대기열/과밀 표시
4. 시간에 따른 수요 증가
5. 실패 조건과 점수
6. POI/건물 밀도를 이용한 자동 Demand Zone 생성
7. 원하는 위치 검색 및 플레이 영역 선택 UI
