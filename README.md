# Flow Control — Procedural Puzzle Prototype

Flow Control은 **이미 존재하는 네트워크 위에서 여러 흐름이 동시에 목적지로 이동하고, 플레이어가 제한된 규칙 변경으로 병목을 줄이는 실시간 퍼즐**을 테스트하는 프로젝트입니다.

현재 단계에서는 OpenStreetMap과 버스 테마를 사용하지 않습니다. 먼저 절차 생성된 그래프만으로 반복 플레이가 재미있는지 검증합니다.

## 핵심 아이디어

Mini Metro가 `네트워크를 만든 뒤 흐름을 처리하는 게임`이라면, Flow Control은 반대로:

> **네트워크는 이미 존재한다 → 흐름이 꼬인다 → 플레이어가 규칙을 바꿔 병목을 관리한다.**

## 현재 프로토타입 규칙

- 매 판 새로운 절차 생성 네트워크
- 3개의 색상 흐름
- 각 색은 왼쪽의 `IN`에서 출발해 같은 색의 오른쪽 `OUT`으로 이동
- 흐름은 혼잡도를 고려해 자동으로 경로를 선택
- 도로에는 동시에 통과할 수 있는 양이 제한됨
- 교차점에 대기 흐름이 쌓이면 과부하 게이지가 증가
- 과부하가 일정 시간 지속되면 게임 오버
- 시간이 지날수록 생성 속도가 증가
- 목적지에 도착한 흐름 수가 Score

## 플레이어 조작

도로를 클릭하면 규칙이 순서대로 바뀝니다.

```text
↔  양방향
→  A에서 B 방향만 허용
←  B에서 A 방향만 허용
×  폐쇄
```

양방향이 아닌 도로는 `Control` 1개를 사용합니다.

현재 사용 가능한 Control은 최대 5개입니다.

핵심 트레이드오프:

- 일방통행으로 바꾸면 반대 방향 흐름이 다른 길로 우회함
- 특정 도로의 정면 충돌/혼잡을 줄일 수 있음
- 잘못 바꾸면 다른 교차점에 새로운 병목이 생김
- 도로를 닫으면 강하게 우회시킬 수 있지만 네트워크를 망가뜨릴 수도 있음

## 실행

PowerShell에서 저장소 루트로 이동한 뒤:

```powershell
git pull
.\run_prototype.bat
```

또는 Godot 4.7.x에서 `project.godot`을 직접 열어 실행할 수 있습니다.

현재 프로젝트 이름은 `Flow Control Prototype`입니다.

## 버튼 / 키보드

- `START / PAUSE / RESUME`: 시뮬레이션 제어
- `RESET`: 같은 맵에서 처음부터 다시 시작, 도로 규칙 초기화
- `NEW MAP`: 새로운 절차 생성 맵
- `Space`: 시작/일시정지
- `R`: Reset
- `N`: New Map

## 이번 테스트에서 볼 것

이번 버전에서 중요한 건 그래픽이나 테마가 아닙니다.

- 흐름이 막히는 위치를 보고 자연스럽게 개입하고 싶어지는가?
- 도로 방향 하나를 바꿨을 때 병목이 풀리는 게 만족스러운가?
- 하나를 해결했더니 다른 곳이 터지는 상황이 재미있는가?
- Control 5개 제한 때문에 선택을 고민하게 되는가?
- 게임 오버 후 `NEW MAP` 또는 `TRY AGAIN`을 누르고 싶은가?

이 다섯 질문이 대부분 YES가 아니면 콘텐츠를 더 붙이지 않고 코어 규칙부터 다시 바꿉니다.

## OSM 관련

OpenStreetMap은 현재 프로토타입에서 제거했습니다.

절차 생성 버전 자체가 재미있다는 것이 확인된 뒤에만 선택적으로 검토합니다.

가능한 장기 구조:

- Procedural / Endless — 메인 모드
- Daily Seed — 동일 맵 경쟁
- Real World — OSM에서 재미있는 그래프를 추출하는 별도 모드

OSM은 게임의 필수 의존성이 아니라 **추가 맵 소스 및 마케팅 훅**으로만 고려합니다.
