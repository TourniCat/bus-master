# Flow Control — Procedural Puzzle Prototype

Flow Control은 **이미 존재하는 네트워크 위에서 여러 흐름이 동시에 목적지로 이동하고, 플레이어가 제한된 규칙 변경으로 병목을 줄이는 실시간 퍼즐**을 테스트하는 프로젝트입니다.

현재 단계에서는 OpenStreetMap과 버스 테마를 사용하지 않습니다. 먼저 절차 생성된 그래프만으로 반복 플레이가 재미있는지 검증합니다.

## 핵심 아이디어

Mini Metro가 `네트워크를 만든 뒤 흐름을 처리하는 게임`이라면, Flow Control은 반대로:

> **네트워크는 이미 존재한다 → 흐름이 꼬인다 → 플레이어가 규칙을 바꿔 병목을 관리한다.**

## v0.2.0 — Adaptive Flow

이번 버전의 목표는 **플레이어가 해결할 수 없는 구조적 병목 때문에 억울하게 죽는 상황을 줄이는 것**입니다.

### Dynamic Routing

흐름은 교차점에 도착할 때마다 경로를 다시 계산합니다.

경로 비용에는 다음을 반영합니다.

- 이동 거리
- 현재 도로 점유율
- 이미 꽉 찬 도로에 대한 큰 패널티
- 다음 교차점의 대기열
- 플레이어가 설정한 일방통행/도로 폐쇄

따라서 가까운 길이 막혔으면 다른 우회로가 실제로 더 매력적인 경로가 됩니다.

### Solvability Guard

절차 생성 맵은 각 색상의 `IN → OUT`에 대해 단일 도로 하나가 끊겼을 때도 대체 경로가 남도록 검사합니다.

필요하면 생성기가 추가 shortcut을 넣습니다.

또한 색상별 동시 유입량에 안전 상한을 두어, 시간이 지났다는 이유만으로 생성량이 네트워크의 물리적 처리 가능 범위를 끝없이 넘어가지 않게 합니다.

즉 실패는 가능한 한:

> **플레이어가 만든 방향/폐쇄/병목 판단 때문에 발생해야 한다.**

을 기준으로 합니다.

### Infrastructure Rewards

Score가 일정 수준에 도달하면 게임이 잠시 멈추고 인프라 보상을 선택합니다.

현재 임시 기준:

- 25 Score
- 65 Score
- 115 Score

선택지:

- `WIDEN` — 도로 하나의 Capacity +1
- `BYPASS` — 가까운 두 교차점을 새 연결도로로 연결
- `+CTRL` — 동시에 사용할 수 있는 Control +1

`BYPASS`를 선택하면 첫 교차점과 두 번째 교차점을 차례로 클릭합니다.

## 기본 규칙

- 매 판 새로운 절차 생성 네트워크
- 3개의 색상 흐름
- 각 색은 왼쪽의 `IN`에서 출발해 같은 색의 오른쪽 `OUT`으로 이동
- 도로에는 동시 통과 Capacity가 존재
- 교차점에 대기 흐름이 쌓이면 과부하 게이지 증가
- 과부하가 일정 시간 지속되면 게임 오버
- 시간이 지날수록 생성 속도 증가
- 목적지에 도착한 흐름 수가 Score

도로를 클릭하면:

```text
↔  양방향
→  A에서 B 방향만 허용
←  B에서 A 방향만 허용
×  폐쇄
```

순서로 바뀝니다.

양방향이 아닌 도로는 `Control` 1개를 사용합니다. 기본 Control 한도는 5개입니다.

## 실행

PowerShell에서 저장소 루트로 이동한 뒤:

```powershell
git pull
.\run_prototype.bat
```

또는 Godot 4.7.x에서 `project.godot`을 직접 열어 실행할 수 있습니다.

현재 프로젝트 이름은 `Flow Control Prototype`입니다.

## 버튼 / 키보드

- `START / PAUSE / RESUME`: 시뮬레이션 제어
- `RESET`: 같은 맵에서 처음부터 다시 시작. 도로 규칙과 인프라도 초기화
- `NEW MAP`: 새로운 절차 생성 맵
- `Space`: 시작/일시정지
- `R`: Reset
- `N`: New Map

## 이번 테스트에서 볼 것

이번 버전에서 가장 중요한 질문은 다음입니다.

- 꽉 찬 도로를 피해 흐름이 실제로 다른 길로 우회하는가?
- 플레이어가 잘못 설정한 방향 때문에 생긴 병목과 시스템 자체의 불가능한 병목이 구분되는가?
- WIDEN/BYPASS/+CTRL 중 무엇을 고를지 고민이 생기는가?
- BYPASS를 만든 뒤 답 없던 병목이 풀리는 순간이 만족스러운가?
- 게임 오버가 났을 때 `내가 다르게 했으면 살릴 수 있었다`는 느낌이 드는가?

마지막 질문이 NO라면 난이도와 생성 규칙을 다시 조정합니다.

## OSM 관련

OpenStreetMap은 현재 프로토타입에서 제거했습니다.

절차 생성 버전 자체가 재미있다는 것이 확인된 뒤에만 선택적으로 검토합니다.

가능한 장기 구조:

- Procedural / Endless — 메인 모드
- Daily Seed — 동일 맵 경쟁
- Real World — OSM에서 재미있는 그래프를 추출하는 별도 모드

OSM은 게임의 필수 의존성이 아니라 **추가 맵 소스 및 마케팅 훅**으로만 고려합니다.
