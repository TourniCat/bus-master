# Bus Master — Product Vision

> Status: Pre-production / Prototype
> Working title: **Bus Master**
> Last updated: 2026-09-10

## 1. High Concept

**실제 지구상의 원하는 지역을 선택하고, 그 지역의 실제 도로망·건물 배치·POI를 단순화한 2D 지도 위에서 제한된 버스와 노선을 이용해 계속 증가하는 이동 수요를 최대한 오래 처리하는 실시간 노선 최적화 퍼즐 게임.**

핵심 판타지:

> **Every city is a puzzle.**
>
> 내가 아는 실제 길 위에서, 가장 효율적인 버스망을 만든다.

Bus Master는 도시 건설 게임도, 버스 회사 경영 시뮬레이션도 아니다. 핵심은 **관찰 → 정류장 배치 → 노선 설계 → 운행 → 병목 발견 → 재설계 → 결국 붕괴 → 재도전**이다.

---

## 2. 제품 방향 — 확정

### 2.1 핵심 장르

- Route Optimization Puzzle
- Real-time Transport Puzzle
- Real-world Map Puzzle
- Light Simulation

레퍼런스 방향은 **Mini Metro / Mini Motorways** 계열이지만, 실제 도시의 도로망을 그대로 퍼즐 제약으로 사용하는 것이 핵심 차별점이다.

### 2.2 한 판 중심 구조

- 플레이어는 세계 지도에서 원하는 지역을 선택한다.
- 선택한 실제 지역이 하나의 퍼즐 보드가 된다.
- 시작 시 정류장, 노선 슬롯, 버스 수는 제한되어 있다.
- 시간이 흐르며 새로운 수요 구역이 활성화되고 기존 수요가 증가한다.
- 플레이어는 정류장 배치, 노선 추가/수정, 차량 재배치 등으로 대응한다.
- 시스템은 점점 감당하기 어려워지고 결국 한 판이 종료된다.
- 목표는 더 오래 버티거나 더 높은 점수를 기록하는 것이다.

**오프라인 진행, 방치형 수익, 장기 자동 성장 루프는 핵심 범위에서 제외한다.**

---

## 3. 핵심 차별점

### 3.1 실제 도시 구조가 퍼즐 보드

Bus Master의 지도는 추상적으로 생성된 노드 그래프가 아니다.

- 실제 도로
- 실제 교차로
- 실제 강/호수/공원
- 실제 철도
- 실제 건물 footprint
- 실제 주요 POI

가 퍼즐의 공간 제약을 만든다.

같은 규칙으로 플레이해도 격자형 도시, 산악 도시, 강을 낀 도시, 교외형 도시, 유럽 구도심은 서로 다른 퍼즐이 된다.

### 3.2 실제 도로를 따라 움직이는 버스

노선은 두 정류장을 단순 직선으로 연결하지 않는다.

플레이어가 정류장을 연결하면 버스는 실제 도로 그래프의 유효 경로를 따라 이동한다.

따라서 다음이 전략 요소가 된다.

- 짧지만 느린 골목
- 멀지만 빠른 간선도로
- 다리/터널 같은 병목
- 일방통행
- 도로 접근성
- 도로 혼잡

### 3.3 어디든 플레이 가능

고정된 도시 목록이 아니라, 가능한 한 플레이어가 직접 지구상의 지역을 선택할 수 있게 하는 것이 장기 목표다.

핵심 마케팅 메시지는 "서울 맵"이나 "도쿄 맵"이 아니라:

> **당신이 아는 도시를 퍼즐로 바꿔라.**

이다.

---

## 4. 비주얼 방향 — 2D Cartographic Puzzle

3D 도시 재현 및 Kenney풍 자동 건물 생성 방향은 현재 핵심 범위에서 제외한다.

기본 화면은 **평면 지도 기반 2D**로 간다.

### 배경 레이어

- 도로: 얇고 차분한 선
- 건물 footprint: 낮은 대비의 면
- 공원/숲: 별도 영역색
- 강/호수: 별도 영역색
- 철도: 보조 선
- 주요 POI: 간결한 아이콘/마커

### 게임 레이어

배경 지도보다 훨씬 강한 대비로 표시한다.

- 정류장
- 노선
- 버스
- 승객 대기량
- 목적지 수요
- 혼잡 경고
- 환승 지점

**실제 지도는 배경이고, 버스 시스템은 전경이다.**

Mini Metro의 시각 표현을 그대로 복제하지 않는다. Bus Master의 특징은 실제 도로 형상과 지도 구조가 화면에 남아 있다는 점이다.

---

## 5. 핵심 플레이 루프

`지역 선택 → 퍼즐 보드 생성 → 수요 발생 → 정류장 설치 → 노선 연결 → 버스 배치 → 운행 → 대기열/혼잡 증가 → 재설계 → 더 큰 수요 → 붕괴 → 점수 → 재도전`

플레이어가 계속 보게 되는 질문:

- 어디에 정류장을 두는 것이 가장 효율적인가?
- 정류장을 많이 두어 커버리지를 높일 것인가, 적게 두어 속도를 높일 것인가?
- 어느 수요 구역을 먼저 연결할 것인가?
- 새 노선을 만들 것인가, 기존 노선을 연장할 것인가?
- 직통이 좋은가, 환승망이 좋은가?
- 버스를 어느 노선에 추가할 것인가?
- 교통 정체를 피할 것인가, 수요 중심지를 직접 통과할 것인가?

---

## 6. OSM의 역할

OpenStreetMap 계열 데이터를 퍼즐의 **원재료**로 사용한다.

우선 사용 후보:

- road/highway graph
- building footprint
- landuse
- park/green area
- water
- railway
- school/hospital/shop/station/tourism 등 주요 POI
- 가능하면 road classification, lanes, maxspeed, one-way 등 도로 속성

모든 데이터를 현실 그대로 시뮬레이션하는 것은 아니다.

OSM → 정규화 → 단순화 → 게임 규칙 변환 과정을 거친다.

예:

`building + nearby POI + landuse → Demand Zone`

`road class + lane data + geometry → Speed/Capacity`

`park/water/railway polygon → Map Barrier / Demand Modifier`

---

## 7. Demand Zone

건물 하나하나가 승객을 생성하지 않는다.

주변 건물과 POI를 묶어 게임용 **Demand Zone**을 생성한다.

초기 카테고리 후보:

- Residential
- Office
- Education
- Commercial
- Medical
- Station / Transport Hub
- Tourism / Leisure

Demand Zone은 지도 위에 실제 건물을 유지하되, 게임 정보로는 하나의 수요 중심처럼 동작한다.

시간이 흐르며 모든 Zone이 처음부터 최대 수요를 내는 것이 아니라, 일부 Zone이 차례로 활성화되거나 수요 강도가 증가한다.

도시는 그대로 있고 **퍼즐의 압박만 성장한다.**

---

## 8. 정류장

정류장은 기본적으로 플레이어가 도로변에 직접 배치한다.

핵심 트레이드오프:

- 정류장이 많음 → 도보 접근성 증가 / 버스 운행속도 감소
- 정류장이 적음 → 버스 운행속도 증가 / 도보 접근성 감소

건물/수요 Zone은 일정 도보 반경 안의 정류장을 사용할 수 있다.

기존 실제 버스정류장 정보는 향후 선택적 보조 기능 또는 챌린지 규칙으로 활용할 수 있지만, 기본 퍼즐은 플레이어의 자유로운 노선 설계를 우선한다.

---

## 9. 노선과 버스

### 노선

- 색상으로 구분
- 정류장을 순서대로 연결
- 실제 도로 그래프를 따라 경로 생성
- 운행 중 수정 가능
- 노선 슬롯은 제한 자원

### 버스

- 각 노선에 배치
- 정원 제한
- 정류장에서 승하차
- 도로 상태에 따라 이동속도 변화 가능

향후 특수 자원 후보:

- 대형버스
- 미니버스
- 급행 운행
- 버스전용차로
- 환승 허브

특수 요소는 핵심 노선 퍼즐이 재미있다는 것이 검증된 후 추가한다.

---

## 10. 승객과 수요

승객은 그래픽 캐릭터 단위가 아니라 목적지 수요 단위로 시뮬레이션한다.

핵심 수요 유형:

- 주거 → 업무
- 주거 → 교육
- 주거 → 상업
- 교통 허브 → 주변 지역
- 관광/공원/랜드마크

시간대에 따라 방향이 변할 수 있다.

- 아침: 주거 → 업무/교육/역
- 낮: 상업/의료/관광
- 저녁: 업무/교육/역 → 주거

현실의 실제 인구/교통량을 1:1 복제하지 않는다. 실제 도시 구조를 바탕으로 **게임적으로 읽기 좋은 수요**를 생성한다.

---

## 11. 자원 제약

퍼즐은 제한된 자원 때문에 발생한다.

초기 후보:

- 노선 슬롯
- 버스 대수
- 정류장 설치 수

일정 시간 또는 점수 구간마다 자원 선택 보상을 제공하는 방향을 검토한다.

예:

> **버스 +2** 또는 **신규 노선 +1**

장기적으로는 지역 구조에 따라 다른 선택지가 의미를 갖게 하는 것이 목표다.

---

## 12. 실패와 점수

메인 모드에는 명확한 실패가 존재한다.

현재 가장 유력한 실패 규칙:

- 특정 정류장의 과밀 상태가 일정 시간 이상 지속되면 실패 게이지가 증가한다.
- 과밀을 해결하면 게이지가 회복된다.
- 한계에 도달하면 해당 판 종료.

점수 후보:

- 총 수송 승객
- 운영 시간/일수
- 평균 대기시간
- 최고 동시 대기량
- 최종 노선 수
- 도시별 최고점수

핵심 목표는 **실패 후 다른 노선 구조로 즉시 다시 시도하고 싶게 만드는 것**이다.

---

## 13. 지도 데이터 오류와 사용자 보정

실제 지도 데이터는 완벽하지 않다는 것을 전제로 한다.

장기 기능:

- 건물/POI 용도 수정
- 일부 도로 속성 수정
- 수정 내용은 원본과 분리된 override 데이터로 저장
- Steam Workshop 등에서 지역 보정팩 공유

예상 구조:

`Base Map Data → Game Interpretation → Local Override → Community Override`

이 기능은 퍼즐 핵심이 아니라 실제 지역을 사용하는 경험의 품질을 높이는 보조 시스템이다.

---

## 14. 명시적으로 하지 않는 것

핵심 범위에서 제외:

- 3D 도시 자동 생성
- 실제 건물 외형 재현
- 방치형 수익
- 오프라인 성장
- 버스 회사 경영
- 직원/정비/급여 시스템
- 도시 건설
- 현실 교통량 1:1 복원
- 모든 주민/차량 개별 시뮬레이션

---

## 15. 플랫폼 방향

PC와 모바일 모두 고려한다.

핵심 조작은 터치/마우스 양쪽에 자연스럽게 설계한다.

- 지도 이동/줌
- 도로변 클릭/터치로 정류장 배치
- 정류장 드래그 또는 순차 선택으로 노선 생성
- 노선 수정
- 버스 증감
- 일시정지 / 배속

2D 지도 기반 구조는 모바일 성능과 UI에도 유리하다.

---

## 16. 현재 개발 우선순위

1. **실제 OSM 소지역을 2D 게임 보드로 표시**
2. 도로 그래프 생성
3. 건물/공원/물/철도 레이어 표시
4. 지도 위 자유 정류장 배치
5. 정류장 간 실제 도로 경로 생성
6. 버스가 해당 경로를 따라 이동
7. 최소 Demand Zone 자동 생성
8. 수요 증가/과밀/실패 규칙
9. 퍼즐 밸런스 테스트
10. PC/모바일 조작 검증

현재 가장 먼저 증명해야 할 것은:

> **실제 도시의 복잡한 도로망이, 보기 좋은 2D 퍼즐 보드로 변환될 수 있는가?**

이다.
